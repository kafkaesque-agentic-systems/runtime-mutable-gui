# Intake: <<project name>>

Answer under each question. Leave nothing blank: write "none" or "you decide" where that
is the answer. "You decide" becomes a decision the design records for you to ratify.

## 1. Product

1. What is it, in one sentence?
2. Who uses it, and what do they do with it first?
3. What must it never do or never lose?
4. What does "version 1 is done" look like, as something you can demonstrate?

## 2. Scope

5. List the features of version 1, one per line.
6. What is explicitly not in version 1?

## 3. Technology

7. Language, framework and runtime you require (with versions if you care).
8. Technologies you forbid.
9. Where does it run (operating systems, container, browser, device)?
10. External services or APIs it talks to. For each: who supplies the credentials?

## 4. Data

11. What does it store? Name the main things and their important fields.
12. Which identifiers or file formats can never change once released?
13. How much data, how many users, how fast must it respond?

## 5. Quality

14. Which tests do you require (unit, integration, end to end, performance)?
15. Lint, formatting and type-checking rules you require.
16. Security or privacy rules.

## 6. Edge cases

17. What bad input or failure do you already know it must handle?
18. What happens when an external service is down?

## 7. Working agreements

19. Anything that needs you in person (hardware, a paid service, a manual check)?
20. Anything else the engineer must know.
